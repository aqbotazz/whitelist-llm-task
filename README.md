# Извлечение данных из документов (тестовое задание LLM Engineer)

CLI получает текст документа (счёт, коммерческое предложение, акт) и возвращает JSON
по фиксированной схеме. Главная цель — **не выдумывать**: чего нет в документе, то `null`.

> Черновик. Разделы будут дополняться по мере работы.

## Запуск с нуля

Нужен Python 3.10+ (проверено на 3.12).

```bash
git clone <ссылка на репозиторий>
cd whitelist-llm-task
make install
make test
make eval
```

## Структура

```
extractor/schema.py   # схема выхода (pydantic)
data/docs/            # тестовые документы
data/expected/        # эталонные JSON
data/llm_cache/       # записанные ответы модели
tests/                # тесты pytest
eval.py               # мини-eval
```

## Тестовый набор

11 документов в `data/docs/`, к каждому эталон в `data/expected/` с тем же именем.
01–03 — от заказчика, 04–11 — свои.

| № | Что проверяет |
|---|---|
| 01 | Счёт заказчика; БИН с неверной контрольной суммой; что считать «итого» |
| 02 | КП: нет БИН/номера/НДС/итога, две даты (срок действия и составление), qty не указано |
| 03 | Казахско-русский текст, OCR-ошибки в БИН, «қазан» = октябрь, сумма прописью, «НДС не облагается» |
| 04 | Акт в USD, исполнитель и заказчик с разными БИН |
| 05 | Счёт, где БИН покупателя стоит раньше БИН поставщика |
| 06 | **Сложный:** сумма только прописью по-русски, ИП с ИИН, нет количества и цены |
| 07 | **Сложный:** две разные суммы «к оплате» и две даты документа |
| 08 | **Сложный:** OCR-шум в суммах и дате, нечитаемая сумма НДС (нельзя досчитать) |
| 09 | **Сложный:** полностью на казахском, НДС записан как ҚҚС |
| 10 | Ставка «НДС 16%» без суммы — НДС не считаем; двуязычное название; EUR |
| 11 | **Сложный:** письмо-приглашение, не счёт/КП/акт → `unknown`; внутри есть сумма и даты-ловушки |

Поле `warnings` в эталоне — это описание предупреждений, которые система обязана выдать,
а не точный текст. `field_confidence` в эталоне пустой: его считает код, с эталоном его не сравниваем.

## Решения по неоднозначностям

1. **`total_amount`** — итоговая сумма **к оплате** (с НДС, если он есть), а не «итого» без НДС.
2. **«НДС не облагается» / «Без НДС»** → `vat_amount = 0`: документ прямо говорит, что НДС нет.
   Это факт из текста, а не расчёт. Если про НДС ничего не сказано или указана только ставка
   («НДС 16%» без суммы) → `null`. Сами НДС не вычисляем.
3. **Две суммы «итого»** — берём ту, что сходится с суммой строк (+ НДС); если не сходится ни одна —
   последнюю сумму «к оплате». В обоих случаях — warning.
4. **Две даты** — противоречием считаем только случаи, когда обе даты претендуют на роль даты документа.
   Срок действия КП, срок оплаты, дата мероприятия — это другие роли, не противоречие.
   Если противоречие есть — берём дату из заголовка (рядом с номером документа) + warning.
5. **OCR-ошибки** — исправляем только путаницу «буква вместо цифры» в числовых полях
   (O/о→0, l/I/i→1, в БИН, датах и суммах) и только если результат однозначен.
   После исправления — warning и пониженный confidence. Нечитаемое (`1O #8~`) → `null` + warning.
6. **Двуязычное название** — берём русский вариант с правовой формой (`ТОО "Кокжиек Курылыс"`).
   Если название есть только на казахском — берём как написано, не переводим.
7. **БИН** — только поставщика (исполнителя), БИН покупателя игнорируем. У ИП вместо БИН — ИИН,
   записываем его в `supplier_bin`. БИН с неверной контрольной суммой **не обнуляем** (он есть
   в документе), но снижаем confidence и пишем warning.
8. **`qty` / `price`** — не указаны → `null`, а не 1. `price` — цена за единицу.
9. **Тип документа** — по заголовку: «шот-фактура» (каз.) = счёт-фактура → `invoice`.
   Если номер/текст намекает на другой тип (`AKT-09` у шот-фактуры) — warning.
10. **`unknown`** — для документа не из списка (письмо, приглашение) все поля `null`:
    отправитель письма — не «поставщик», а сумма в тексте — не сумма документа.
